# 变化图与「最强应手」选点策略

2026-09-11 定稿。回答两个问题：变化图长什么样、白棋的应手凭什么算"最强"。

---

## 1. 变化图：一张盘，棋子正中央写 1..N

用户 2026-09-11 定稿：**不要拆成 5 张小图**，就画传统棋书那种「参考图」——
一盘棋上按手数标 1、2、3、4、5，数字压在棋子正中央。

- 盘面取**走完最后一手**的棋形（不是题面），这样 N 个编号全都落在实子上。
- 某手的子中途被提掉 → 该点画**虚线环 + 珊瑚色数字**，表示"这手曾落在此处"。
- 最后一手加一圈浅色光晕，一眼定位。
- 右侧图例：序号 / 落子方 / 坐标 / 该手后的黑方领先目差 / 提子数；
  按「目差最顽强」选出的手标 `*`，访问量 <300 的手标"（仅 N 次访问）"。
- 底部：正解、次选差距、对手最强抵抗、双解/改判提示。

实现：`solver.variation_single()` + `recognition/board.py` 的 `nums` 参数。

## 2. 白方应手：从「沿用 PV 尾部」改成「逐手独立搜索」

### 旧做法（已废弃）

一次根查询 → 拿 `moveInfos[0].pv` → 直接取 PV 的第 2、3、4、5 手当双方应对。

问题：PV 越往尾部，访问量越低、越不可信。实测（`diag_bestmove.py`，
3000 visits，2026-09-11）6 题里有 5 题出现 PV 与逐步重算不一致：

| 题 | 第几手 | 根 PV 给的 | 独立搜索改判 |
|---|---|---|---|
| 全局题1 | 5 | Q3 | M5 |
| 全局题2 | 2/3/4/5 | R18/S17/S19/T17 | H16/G16/G17/H15 |
| 全局题3 | 2/3/4/5 | H18/H19/J19/G19 | L16/J19/L14/M15 |
| 手筋题2 | 4/5 | F8/G4 | G8/F8 |
| 手筋题3 | 3/4/5 | C7/F6/D7 | D7/C3/C7 |
| 手筋题1 | — | 5 手全一致 | — |

（同一题两轮重跑会差一两手，KataGo 有 nnRandomize；但"6 题里 5 题出现改判"
这个结论两轮都一样。）也就是：**前 2 手基本可信，第 3 手往后不能信 PV**。

### 新做法

`depth` 次查询，每落一手就对**新局面**重新完整搜索一次（visits 不变），
再取该局面的最优手。收尾再查一次拿到最终目差。

这就是 KaTrain / Lizzie / AI Sensei 的"逐步分析"模式——业界讲题都这么干，
没有谁复用上一次搜索的 PV 尾部。代码在 `solver.solve()`。

代价：一题从 2 次查询变成 depth+1 次。19 路 depth=5、3000 visits 约 1 分钟。

## 3. "最强"按什么算？目差，但必须带访问量门槛

KataGo 给的三个量：`winrate`（胜率）、`scoreLead`（目差）、`utility`（混合）。
`moveInfos` 的顺序是 KataGo 自己的稳健序（LCB），**不是**裸 scoreLead 排序。

两个都会踩的坑（实测）：

1. **别用胜率挑"最强抵抗"**。大胜/大败已定时 AI 会随手（赢定了不在乎掉目），
   全局题2 黑已落后 9 目、胜率 0.008，胜率维度上白怎么走都是赢，只有目差
   才分得出哪手最狠。讲题讲的是"最大抵抗"，所以看 scoreLead。

2. **别裸按 scoreLead 排序**。只被访问 1 次的候选，scoreLead 完全是噪声：
   实测全局题2 白方候选里 K10 报 `lead=+0.27 / vis=1`，而实算该局面是 −9 目。
   直接取 min(scoreLead) 会挑到这种幻觉手。

### 现在的策略（`solver._pick`）

1. 默认信引擎首选（KataGo 的排序本身已经稳健）。
2. `tough=True` 时做「最顽强」校验：在 `visits >= 30` 的候选里，黑取
   scoreLead 最大、白取最小（= 让黑领先最少）。
3. 只有当它比引擎首选便宜 `>= 0.3` 目才真的替换——差零点几目是搜索噪声。
4. 替换了就在图上标 `*` 并写进讲解，说明这是最大抵抗、不等于唯一应手。

实测（同一批题跑两轮，3000 visits）：

- 第 1 轮全局题2 第 2 手：首选 R18（vis 2915, −9.03）与 H16（vis 305, −8.96）
  只差 0.07 目 < 0.3 → **保持首选**，挡掉一次噪声。
- 第 2 轮同一题同一手：H16 被搜到 136 次、收益 1.2 目 → **切成 H16 并标 \***。
- 全局题1 第 5 手（黑已领先 29 目、胜率饱和）：引擎首选 Q3 明显是"赢定了随手"，
  目差准则换成 M5，便宜 1.4 目 → 切。这正是要 tough 的原因。

同一手两轮访问量能差一倍（305 vs 136），说明低访问候选的目差估值天然不稳
——所以既要设门槛，也要把访问量印在图上，让读者知道这手有多可信。

## 4. 还差什么（下一步）

- **双解题要穷举守方应手**：手筋题3 的 G6 / F3 只差 0.3 目（3000 visits），
  属双解。严格做法学 KataGo 官方解死活题：`allowMoves` 把双方锁进局部矩形，
  把守方所有应手都过一遍，确认正解对**每一手**都成立。现在只给了主变。
- **排序可用 LCB 代替均值**：`moveInfos` 里有 `lcb/utilityLcb`，用下界排序比
  均值更抗噪，适合低 visits 场景。
- **全局题的"正解"语义**：全局题是实战局面，第 1 手只是"当前最大的一手"，
  不是死活题那种唯一正解，讲解文案别写成"正解唯一"。
