# 设计思路

## 1. 问题从哪来

孩子业余 4 段，每天做死活题。家长不会围棋，无法当场批改。真实痛点是两个：

1. **反馈不及时**——做完要等到下次上课才有老师看，错题的"当时在想什么"早就忘了；
2. **反馈没深度**——就算有人批改，给一句"错了，正解是这里"没有价值。死活题训练的是"怎么找要点"，不是"记住答案"。

所以这个工具的目标不是"自动判对错"，而是：**在孩子还记得自己思路的时候，给出一个能推进他思考的反馈**。

## 2. 设计原则

| 原则 | 具体做法 | 反例（不做） |
|---|---|---|
| **不替孩子下棋** | 讲解走四步启发阶梯（定目标→数眼位→找要点→自验），每层只给一个提示 | 直接显示正解图 |
| **不确定就交给人** | 手写编号低置信标 `?`；棋形识别结果必须人工确认才批改 | 信心不足时仍猜一个答案 |
| **识别是头号嫌疑** | 引擎结论与孩子/题面矛盾时，先怀疑自己识别错了一子 | 直接判孩子错 |
| **先后手不让系统猜** | 题型（黑先杀/黑先活/白先杀/白先活）必选 | 根据"哪边有杀着"自动推断 |
| **反馈分层次** | 要点对不对（最重要）→ 结论对不对 → 次序对不对 | 只报"对/错" |

## 3. 六步管线（框架设计，每步都对应一个已发生过的教训）

```
① 题型确认 ── 系统不猜先后手
        ↓
② 棋形识别 + 画回确认（硬性门禁，未确认不批改）
        ↓
③ 手写编号识别 + 按顺序确认
        ↓
④ KataGo 验证（正解 / PV / 孩子变化逐手评分）
        ↓
⑤ 三层比对（要点 / 结论 / 次序）+ 一致性警报
        ↓
⑥ 四步启发阶梯讲解 + 可打印讲题卡
```

每一步的来历：

- **① 题型必选**：杀和活是一体两面，同一个棋形"黑先杀白"和"白先做活"是同一道题的两面。曾因默认黑先 + 自假设，把两道题的题型判反。
- **② 画回确认门禁**：识别差一子、差一行就能把净活翻成打劫。曾因赶时间跳过这步，导致首着读错 + 题型判反。
- **③ 编号确认**：手写数字小、斜、压线，透视下 2 会被读成 1（置信度还高达 0.70）。宁可标 `?`。
- **④ KataGo 验证**：，家长不会围棋，判定只能靠引擎，但引擎会受空旷区域干扰，需要紧贴棋盘建模 + 让先测试。
- **⑤ 三层比对**：要点对了但次序错（先冲后点 vs 先点后冲）在实战中后果完全不同，值得单独评。
- **⑥ 启发阶梯**：这是"深度思考"的载体，也是家长能拿来讲的唯一抓手（家长自己不会下棋，但能照着四步提问）。

## 4. 识别管线：从照片到坐标

这是整个项目最脆的一环，也是迭代最多的部分。判据链条：

```
HoughLinesP 检印刷线（斜率过滤容忍 ±8° 倾斜）
  → 粗检圆（严参数 param2=28 + 同心孪生去重）
  → 亮度分流：只用黑子圆心算间距先验
  → 点阵相位拟合（扫 anchor，容忍离群证据）
  → 多 param2 投票精检圆
  → 线 + 圆心联合再拟合（补被棋子压断的线）
  → 全交叉点扫描分类（洗掉蓝墨后的灰度图）
```

### 踩过的坑（按发现顺序）

| 现象 | 根因 | 对策 |
|---|---|---|
| 只能检出无子的线 | 棋子把线压断 | HoughLinesP + HoughCircles 圆心融合 |
| 倾斜 ±8° 时线判定失效 | 用固定像素差判水平/竖直 | 改用斜率 `|dy| < 0.15|dx|` |
| `HoughLinesP` 遍历报错 | cv2 5.0 返回 `(N,4)`，旧版 `(N,1,4)` | 遍历前 `reshape(-1,4)` |
| 小棋盘 0 子检出 | 粗检半径窗按图宽估，小于石子半径 | 两遍走：网格定后按间距重检 |
| 间距被带歪（44 当成 22） | **幽灵圆**：四子拐角处 4 段圆弧被组合检成圆，圆心落在半间距位置 | 幽灵圆全是亮色且描边环比真白子还高，单点验证滤不掉 → 只用黑子圆心（亮度 <110 近零误判）算间距先验 |
| 间距平票/混入假值 | 半间距是任何距离的"公约数"；直方图 bin 把 44±2 劈半输给 62；相对容差让 √5 距离混进来 | 细粒度 0.5 步长扫描 + 绝对容差 `max(2.5, 0.05·k·s)` + 同分取大 s + 下限 s≥20 |
| 棋盘边多出幻影行 | 点阵外推节点没有证据支撑 | 节点只保留证据范围 ±0.3s 内 |
| 边缘空点被判成白子 | 边/角节点十字只有半边线，暗像素天然减半 | 边缘节点只采棋盘内侧半窗 + 按采样长度归一化成占比 |
| 空点被判成黑子（生产级 bug） | **蓝墨在灰度图里是暗色**，孩子恰好在空点上写编号 | 棋形识别全程用洗掉蓝字的灰度图，数字识别仍用原彩图 |
| 透视下整条线漏掉 | 节点拟合偏差达 6.5~9px，窄采样带错过线 | 采样带 ±10px（推导：band≥12 白子描边环会进带造成反误判） |
| 空点逼近黑子阈值 | 空点中心压线亮度 116，距阈值 110 一线之隔 | 黑子判据改为**圆盘暗像素占比** >0.5（空点仅 ~0.3） |

核心判据"印刷图有子必盖线"：黑子看圆盘暗占比、白子看网格线被盖住、其余是空点。仅适用于印刷题图，真实木盘（木纹 + 透视）不适用。

### 手写编号识别

HSV 蓝阈值（H 85~135）→ 连通域 → 邻近碎片合并 → 补边成方形缩放 → cv2 渲染多字号模板 `TM_CCOEFF_NORMED` 匹配。**双重门槛**：`conf ≥ 0.5` 且 `top1 - top2 ≥ 0.02`——透视剪切下 2→1 误读置信度高达 0.70，但第二名几乎并列，靠间距门槛拦掉。

## 5. 批改逻辑

- **正解**：KataGo 在紧贴棋盘（切掉空旷区）上跑，取 `moveInfos[0].pv`。
- **死活判定**：PV 走到定型后，看目标棋群 `ownership` 均值——>0.6 活、<-0.6 死、中间"不明"（通常是劫）。再用**让先测试**（`moves=[["B","pass"]]`）判无条件死活。
- **孩子变化逐手评分**：每手给出 `rank`（在候选中排第几）、`is_best`、`lead_gap`（与最佳手的目差），从而区分"要点对、次序错"和"要点就不对"。
- **一致性警报**（触发即停止判定，回查棋形）：
  - 题面写了"劫"但引擎判净死/净活
  - 引擎与孩子答案、书后答案两边都矛盾
  - 结论与题感不符（标着"3-5 步变化"的题却一动就净活）

## 6. 讲解设计：四步启发阶梯

1. **定目标**：这题是要杀还是要活？
2. **数眼位**：这块棋现在能做出几只眼？缺什么？
3. **找要点**：这种形状的要点通常在哪（扑、点、夹、立……）？
4. **自验**：对方最强抵抗是什么？你挡得住吗？

每层只给一个提示，答对后追问"为什么别的点不行"。家长即使完全不会下棋，也能照着这四步提问——这是"家长模式"的核心：让不懂棋的家长也能完成一次有质量的复盘对话。

## 7. 工程决策

- **本地网页 App（而非微信小程序/原生 App）**：不需要上架审核、不需要公网服务器、照片不出家门（孩子作业照片的隐私）；手机浏览器直接访问局域网即可。
- **KataGo 常驻进程**：analysis 模式启动一次要加载模型，每次查询 fork 一次不可接受。封装成单例 + 线程锁。
- **题库自动归档**：批改完自动写入 `problems.json`（小棋盘坐标锚定 19 路右上角 + 自动备份 + 写后校验），为后续错题本和周期统计留数据。
- **归档开关**：测试时传 `archive:false`，避免测试数据污染生产题库。
