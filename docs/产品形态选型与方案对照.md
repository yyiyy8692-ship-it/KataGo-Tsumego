# 产品形态选型 vs 邮箱方案对照（2026-09-12）

## 一、为什么交付的是 Web App，不是微信小程序

用户要的是「三种输入方式 + 拆题 + 给答案」。形态选择的真实约束在**算力**：

| 形态 | 门槛 | 是否可行 |
|---|---|---|
| 微信小程序 | 注册主体 → 服务器 + **域名备案** + HTTPS → 小程序审核（教育类目）；KataGo b18c384nbt 需 GPU 服务器常驻 | 可行但成本高，且**必须上云** |
| 原生 APP | iOS 需开发者账号 + TestFlight/上架审核；Android 略宽松 | 同上，还要上云 |
| **本机 Web App（本次交付）** | 零门槛，跑在已有 Mac mini 上 | **已交付** |

关键点：KataGo 是本地二进制 + 本地权重，一局 3000 visits 在 Mac mini 上约 30 秒。
挪到云端意味着长期租 GPU 实例，而题册批改是每天几十分钟的低频需求，云成本/收益不成立。

**但架构是向前兼容的**：现在的 `web/app.py` 已经是标准 HTTP 服务
（`/api/solve` + `/api/task/<tid>`），将来若真要小程序，只需给它配 HTTPS 域名，
小程序前端换成调用这两个接口即可，识别与求解一行不用改。

手机上的体验：Safari/微信内打开 → 「分享 → 添加到主屏幕」，图标、全屏、
无地址栏，和原生 App 的差别只在 callout（拍照用 H5 `capture`，效果一致）。

### 为什么拆成「识别 → 确认 → 点算」两段

原来的流程是上传即全算，实测两个问题：**一页 6 题要 4~6 分钟**，而家长多数时候
只要其中 2~3 题；更要命的是**识别错了还硬算 5 分钟**——这是最浪费的一种失败。
所以识别阶段（几秒）结束后先停住，把每题的棋形画出来（含「和拍的原图对照」），
确认无误才点「✓ 棋形对了，算答案」；认错的题可以直接「这题不要」剔掉。
想省事就点「全部计算」。

实现要点：计算必须**串行**——KataGo 单实例、神经网络吃满 CPU/GPU，并发只会
互相拖慢，所以是单工作线程 + FIFO，而不是每点一题开一个线程。轮询接口增加了
`?have=0,2` 参数，前端已拿到答案的题不再回传 SVG（一张上百 KB，每次轮询重发
纯属浪费）。

## 三、对照下来确实还差的四件事

### 1. df-pn「证明级」求解（方案有，我们没有）

- df-pn 能给**证明级**死活结论（净活 / 净死 / 打劫活），KataGo 给的是**统计意义上**
  的最优手（3000 visits 的 LCB 排序）。对标准死活题，df-pn 的结论更硬。
- 但对我们手上这类**混合版面**（19 路全局实战题 + 7×9 手筋题），df-pn 用不上：
  它没有"某块棋是死是活"这个目标域，全局题和手筋题都不存在待证明命题。
- 折中路径：只对手筋/死活题（局部小盘）接 df-pn 做交叉验证，全局题仍用 KataGo。
  **要不要做，取决于是否接受"出题 .vs 讲题"的严格度差异** —— 讲题场景下 KataGo 够用。

### 2. 错题本 / 历史回看（方案有，我们没有）

现在的答案模式是**一次性任务**：页面关掉后只能通过 URL 找回，没有「上周做错的题」
这种列表，也没有按孩子/日期归档。旧批改模式有 `grader.archive`，但没有 Web 浏览界面。
**这是最影响日常使用的一块** —— 练了一学期却看不到进步轨迹。

### 3. 走棋方固定为黑先

当前按用户要求全部黑先（`to_play="B"` 写死）。题册里出现白先的题时需要改代码。

### 4. 讲题卡导出 / 打印

SVG 和 HTML 都在，但没有一键「导出 PDF 给打印」的按钮。

## 四、本次已补的工程质量缺口

- `recognize_auto.py`：**抽出统一的识别入口**。原先整盘优先的逻辑写在 CLI 脚本里，
  Web 端另起炉灶时用了错误的 `recognize`（dict vs 5 元组），6 题全线报
  `too many values to unpack`。现在 CLI 与 Web 共用一份。
- `start.sh`：自动挑选**能 import cv2 与 pymupdf** 的解释器。以前默认 `python3`，
  系统 Python 没装这两个包，会一路跑到用户上传 PDF 时才炸。
- `prepare_pages` 自带 `os.makedirs`，不再依赖调用方先建目录。
- 任务串行（`_RUN_LOCK`）：KataGo 单实例吃满算力，并发提交只会互相拖慢。
- 增量轮询（`?after=N`）：算完一题回传一题，不必每题都重发上百 KB 的 SVG。
